Дата: 5 октября 2026. Данные: `reports/v25-phase0-simulation.full.json`, `reports/v25-phase0-simulation.contrast.json`. Воспроизведение: `npm run v25:parse && npm run v25:source && SIM_SCORING=full npm run v25:simulate` (и `SIM_SCORING=contrast`). Код движка не менялся.

## 1. Источник пакета (`npm run v25:source`) — SOURCE OK

Парсер извлекает 32 neutral, 8 motive, 4 behavior, 21 probe, 50 dev-карточек. Все структурные проверки проходят: счётчики, 16 top-1 на логику и 4/4/4/4 по позициям, ротация probe по вектору (не по букве), control вне пары, позиции target в dev 17/17/16, маршрутизация retry (`retry.01` ≡ только `withdrawal@pressure`), `transfer.contextId ≠ trial.contextId`, достижимость control/trial-withdrawal/retry-trial в каждой из 6 дуг. Агрегатные суммы векторов совпадают с цифрами RECONCILIATION-v2 (achiever 23.80 против ironic 10.35).

## 2. Календарь (измерен на реальных прогонах игры)

59–63 свободных слота за эпизод; сюжетный свободный пул (медиана) 11 / 9 / 18 / 18 сцен на днях 1 / 10 / 20 / 30. 32 neutral почти целиком показываются за 30 дней (в среднем 29–30): диагностика не вытесняется сюжетом, **вес neutral в `weighted()` менять не нужно**.

## 4. Вывод

Gate **не пройден** на текущем scoring v1 (§19.2 спецификации: hit-rate ≥ 95 % для всех восьми): не достигаются Оппортунист, Дипломат, Алхимик и Ироничный. Ошибочных центров нет — героя просто не фиксируют, потому что у поздних и ранних логик в пуле меньше «массы» вектора (доля лидера не доходит до 0.30). Это та же причина, что в отчёте v2.4, и она не устраняется весом neutral, пулом или порогами.

Контрастная оценка (алгоритм `2`) снимает проблему, но оставляет два пятна, которые надо закрывать до включения, а не после: ложный stable у смешанного героя в режиме B (15 % при пороге 10 %) и Алхимик в режиме B (92 %, P90 = 19 день). По плану это отдельное решение пользователя (`algorithmVersion = 2` не входит в v2.5 автоматически).

Не проверено в Ф0: F ≥ 2, motive/behavior-доказательства, retry/dev-карточки в календаре, живой selector (вместо него — модель по измеренным размерам пула).

## 5. Решение и подбор порогов ветки 2 (5 октября, «как лучше?» → рекомендация принята)

`algorithmVersion = 2` — новая неизменяемая ветка рядом с `1`: вклад кейса — контраст «выбранный вариант минус среднее отвергнутых» (отрицательное обнуляется, затем нормировка на 1; если контраста нет — полный вектор). Ветка `1` остаётся как была для старых сохранений.

Оффлайн-сетка порогов `stableCandidate` для контраста (200 прогонов на логику, режимы A / B; min-hit — худшая логика; mixed — ложный stable у смешанного героя):

| minLeaderShare / minDelta / minConfidence | A: min-hit | A: mixed | B: min-hit | B: mixed | worst P90 |
|---|---:|---:|---:|---:|---:|
| 0.30 / 0.10 / 0.6 (как v1) | 98 % | 7 % | 92 % | 15 % | 19 |
| 0.32 / 0.10 / 0.6 | 93 % | 6 % | 93 % | 10.5 % | 17–19 |
| **0.34 / 0.10 / 0.5** | 92.5 % | 4 % | 93.5 % | 7 % | 18 |
| 0.36 / 0.10 / 0.5 | 86.5 % | 1.5 % | 89.5 % | 4 % | 20–21 |

Выбор для ветки 2 на старте: **0.34 / 0.10 / 0.5**. Остальные семь логик ≥ 98 %; нижняя граница определяется Алхимиком (92.5–93.5 %, P90 день 17–18). Остаток — не порог, а масса векторов Алхимика (10.95 из 128 суммарно) и граница Алхимик ↔ Ироничный, которую спецификация сама считает слабой для action-доказательств. Закрывается blind-review/правкой векторов в Ф5, а не новыми порогами. Эти значения предварительные: окончательно фиксируются на реальных переписанных сценах (векторы не меняются при переписывании текста, но sim-модель пула заменится живым selector).
