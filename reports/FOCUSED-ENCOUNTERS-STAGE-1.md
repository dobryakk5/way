## 2. Как работают обе точки (единый фильтр)

1. **Контекст** вычисляется до подготовки кандидатов из `goal`, `declaredIntention`, `evidence` (8 последних), `threads`+`facts`/`opportunity*`/`scheduled`. Профиль героя, `development`, `Card.diagnostic`, `selectionOrigin` в `storyContext.ts` и `focusedEncounters.ts` не читаются (тест-страж по тексту модулей, без комментариев).
2. **Релевантность**: P1 `G∧(L∨T)` · P2 `L∨T` · P3 `G` · P4 `I` (карточка с `story`) · P5 `W` (`worldFallback` ∧ `role: ambient`). Ранжируются только «обычные свободные» сцены (`isFacetWeightedDrawCandidate`); карточка без `story` в активном диапазоне не попадает никуда.
3. **Кубик** (`prepareEncounter`): легаси-shuffle и места под probe/neutral/development не меняются. Позиции, которые в легаси занимали обычные сюжетные сцены, заполняются контекстным списком: P1→P5 без возвратов, внутри уровня — взвешенная выборка без возвращения (`ln(u)/w`, `u` из `deterministicRandom(...,'focus:<id>')`); при ≥2 местах одно резервируется под другую свежую линию/открытую нить, иначе под сцену намерения другой сферы. Затем прежняя итоговая перетасовка и честный кубик. Если контекстных сцен меньше мест — набор не создаётся (`length !== 6`), слот идёт прямым отбором.
4. **Прямой отбор** (`drawFocusedFreePool`): исходный выбор «защищённая vs story» — прежний `weighted`; защищённая карточка возвращается без замены; story заменяется лучшей релевантной (тот же `rankFocusedStory`, тот же ключ веса, поэтому это ровно «первый пик» кубикового списка); если релевантных нет — защищённая карточка той же детерминированной ветки; если нет и её — `FocusPoolEmptyError` (`code: 'FOCUS_POOL_EMPTY'`), без молчаливого возврата в общий пул.
5. Диапазон: `rollout.focusedEncounters ∧ fromDay ≤ day ≤ throughDay`; вне него — прежний алгоритм без изменения порядка RNG.

## 3. Решения по review (внесены в этот коммит)

1. **Намерение** действует не только через P4, но и внутри каждого уровня P1–P5: вес сцены своей сферы × `facetAttention.declaredIntentionMultiplier` (1,15). При включённом `facetAttention` бонус отдельно не добавляется — он уже содержится в `declaredIntentionPrior` (пока у героя меньше `minEvidence` собственных решений), поэтому дважды не применяется. Диагностику, probe и development это не затрагивает.
2. **Прямой отбор**: легаси-разделение «защищённая / сюжетная» сохранено; для сюжетной выбирается уровень среди непустых с весами **8:5:3:2:1** (`DIRECT_TIER_WEIGHTS`, один детерминированный бросок `focus-tier`), затем карточка внутри уровня по весу. Число карточек в уровне на шансы уровня не влияет. Кубик по-прежнему заполняет места P1→P5 с резервом под разнообразие.
3. **Lint** — строгий (реализуется вместе с разметкой в этапе 2).

Прочие трактовки, оставшиеся в силе: число story-мест берётся из легаси-shuffle (доля protected неизменна); диверсификация — «другая свежая линия / нить, иначе намерение другой сферы»; открытость `chain` — фоллоу-ап запланирован и срок не прошёл; `story.lines` допустимы, только если какой-то выбор эту линию пишет.

## 6. Оставшиеся проблемы и риски

1. **`FOCUS_POOL_EMPTY` бросает исключение из `drawCard`/`prepareEncounter`.** В UI это упадёт при включённом флаге, если данные не покрывают контекст. Защита: флаг выключен; lint при включении требует разметку; симуляции этапа 2. Если нужна «мягкая» деградация в проде — это решение вне ТЗ.
2. **Разнообразие прямого отбора.** Около половины свободных показов идёт прямым отбором; после решения review уровни выбираются с весами 8:5:3:2:1, но разнообразие по-прежнему зависит от числа размеченных карточек на разные линии — оценивается сравнением «кубик vs прямой» на реальной разметке (этап 2).
3. **Мало карточек в днях 1–10** (≤19 обычных сцен, часть под `requires`). Дефицит → прямой отбор; в худшем случае — `FOCUS_POOL_EMPTY`. Нужен контентный план (этап 2, аудит 43 сцен).
4. **Дефицит повторяется в течение дня.** Пока набор не создан, `prepareEncounter` пробует снова в следующих слотах того же дня; бросок по-прежнему максимум один (запись `diceHistory` создаётся один раз). Поведение совпадает с легаси-веткой «меньше шести».
5. **Трасса** (`setFocusedTrace`) — глобальный синк; предназначен для тестов/симуляций. Трасса `direct` включает и предварительный вызов `drawCard` внутри `prepareEncounter`, поэтому реальные прямые показы считаются по `draws`, а не по трассе.
6. **Существующие проблемы baseline не затронуты:** два тяжёлых сценарных теста падают по таймауту 20 с при полном параллельном `vitest run` на загруженной машине (отдельно проходят); устаревший `FACET-ATTENTION-SIMULATION-v1.md`; недостижимые `alchemist`/`ironic`.
7. **Не сделано намеренно** (этап 2+): разметка `story` в карточках, UI-тексты `DiceScreen` (§10), `CONTENT_VERSION`/PWA (§13), отчёты `CONTENT-AUDIT`, `SIMULATION`, `REVIEW`.
