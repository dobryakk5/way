# NEUTRAL-DIAGNOSTIC-CONTENT-v1
## «Путь»: независимый neutral-пул для первичной и текущей диагностики логики героя

**Статус:** content draft v1 для blind-review и последующей конвертации в `cards.*.json`  
**Дата:** 5 октября 2026  
**Тип:** независимый диагностический контент; не является development arc

---

# 0. Назначение

Этот пул отвечает на вопрос: **какие логики герой фактически проявляет в обычных жизненных решениях, когда игра ещё не подстраивает ситуацию под гипотезу о нём?**

Основные правила:

- все 32 основные ситуации имеют `selectionOrigin = neutral`;
- ни одна не зависит от `developmentCurrent`, `observedPrimary`, `leadingEdge`, `activeArcId` или stage/profile gating;
- все могут входить в `currentDistribution`;
- у каждой ситуации 4 естественных варианта выбора;
- `developmentWeight = 1.0`: 12 action-only кейсов дают `W = 6` при source coefficient action `0.50`;
- у каждой ситуации отдельный `contextId` и один основной facet;
- названия восьми логик не показываются игроку;
- consequence мира само по себе не считается `behavior`.

Дополнительно описаны 8 опциональных motive prompts и 4 behavior-continuation. Они дают дополнительные evidence исходному кейсу, но не увеличивают `N`.

# 1. Покрытие и баланс

| Параметр | Значение |
|---|---:|
| Основных neutral-ситуаций | 32 |
| Дело и деньги | 8 |
| Отношения | 8 |
| Тело и здоровье | 8 |
| Внутренний мир | 8 |
| Уникальных contextId | 32 |
| Pressure-ситуаций | 8 — по 2 на грань |
| Motive prompts | 8 — по 2 на грань |
| Behavior continuations | 4 — по 1 на грань |
| Action choices | 128 |
| Top-1 каждого из 8 центров | ровно 16 |

Ровный `top-1` баланс — свойство **контент-пула**, а не предполагаемое распределение людей. Он нужен, чтобы авторы сами не создали prior в пользу удобных для написания стадий.

# 2. Формат авторской разметки

`Lead` — только редакторская подсказка. В UI её нет.

`LogicVector` приведён полностью по восьми ключам. Для каждого вектора в этом draft автоматически проверено:

- сумма = `1.0 ± 1e-9`;
- минимум две ненулевые компоненты;
- максимум = `0.60`, то есть ниже лимита `0.70`;
- все значения конечны и неотрицательны.

Rationale заполняется по шести осям `SELF / OTHERS / COMPLEXITY / TIME / PERSPECTIVE / UNCERTAINTY`. Вторичные веса также объясняются текстом, а не существуют только числом.

- PERSPECTIVE — собственная перспектива имеет приоритет. Вторичные сигналы: Дипломат — принадлежность, отношения и социальная норма; Эксперт — правильность, качество и компетентность.
- UNCERTAINTY — неопределённость снижается быстрым действием, контролем или уходом от угрозы.

### D. Вытащить из примеров то, что поможет улучшить итог проекта, и договориться о следующем контрольном результате.

**Lead (не игроку):** Достигатель  
**LogicVector:** `{ opportunist: 0.00, diplomat: 0.00, expert: 0.25, achiever: 0.60, individualist: 0.00, strategist: 0.15, alchemist: 0.00, ironic: 0.00 }`

**Rationale:**
- SELF — роль автора цели и ответственность за результат.
- OTHERS — другие — партнёры и заинтересованные стороны вокруг задачи.
- COMPLEXITY — удерживаются несколько ограничений, ресурсов и приоритетов.
- TIME — проектный горизонт: цель, этапы, срок, измеримый итог.
- PERSPECTIVE — разные позиции учитываются прагматически, если влияют на результат. Вторичные сигналы: Эксперт — правильность, качество и компетентность; Стратег — устойчивость системы, обратные связи и длинный горизонт.
- UNCERTAINTY — принимается рабочая гипотеза: действовать, измерять, корректировать.

# 9. Production-правила

Перед переносом в JSON каждая ситуация проходит blind-review второго редактора.

1. Все варианты должны выглядеть как разумные живые решения, а не «плохой / хороший / мудрый».
2. Редактор, не видящий `Lead` и vectors, должен уметь объяснить различия по шести осям.
3. Если независимые редакторы систематически читают choice иначе, нельзя «дожимать» разметку числом: переписать текст или ослабить вектор.
4. Не использовать слова-маркеры вроде «зрелый», «осознанный», «системный подход» только ради того, чтобы выдать поздний центр.
5. Ни одна карточка этого пула не получает stage/profile gating.
6. Если конкретный показ в будущем выбирается из-за профиля, именно этот показ должен стать `adaptive`, даже если карточка родом из neutral-пула.
7. Outcome мира не становится behavior без отдельного последующего выбора героя.
8. Motive не угадывается из action.
9. Позиция ответа не является диагностическим сигналом. В основном пуле top-1 каждой логики распределён ровно по 4 раза на A/B/C/D.
10. Для motive/behavior-подблоков позиции top-1 распределяются максимально равномерно (разница между позициями для одной логики не более 1, когда это математически возможно).
11. При конвертации в JSON смысл и `LogicVector` привязываются к стабильному `choiceId`, а не к индексу массива.

# 10. Автоматическая структурная проверка v1

- 32 основных кейса;
- 8 кейсов на каждую из 4 граней;
- 32 уникальных `contextId`;
- 128 action choices;
- ровно 16 top-1 choices для каждой из 8 логик;
- 8 pressure-кейсов, по 2 на грань;
- 8 motive prompts, по 2 на грань;
- 4 behavior continuations, по 1 на грань;
- каждый vector содержит 8 ключей;
- сумма каждого vector = 1;
- минимум две ненулевые компоненты;
- `max(vector) = 0.60 <= 0.70`;
- в 32 основных кейсах каждая из 8 top-1 логик встречается **ровно 4 раза** на каждой позиции A/B/C/D;
- positional balance является отдельным валидатором и не заменяет blind-review.

Эта проверка подтверждает только структурную непротиворечивость. Качество разметки должно проверяться независимым редактором и через `simulate-profile`.
